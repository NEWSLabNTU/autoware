Optimizing System Performance¶

Improving Image Transfer Reliability¶

LUCID cameras have various features to improve the reliability of image data transfer. Reliable data transfer usually means minimal dropped packets and data loss.

Packet Resend¶

This is a feature where the software requests the re-transmission of lost packets. Packet resend improves reliability by reducing the number of lost packets, and is intended for use in systems with sporadic packet loss. It does not influence frame rates.

More information about Packet Resend is further covered in a section of our Tech Brief on Gigabit Ethernet.

If you see packet loss or torn images while streaming in ArenaView, you can enable packet resend by setting TL DataStream Parameters -> Buffer Handling Control -> Packet Resend Enable to On.

  • Stop the camera stream before changing the Packet Resend option.
  • StreamPacketResendEnable must be set to a value > 0
  • DeviceLinkThroughputReserve must be set to a value > 0

Packet Delay¶

Packet delay is a feature that lets you configure delays into the tramission of packets. One reason to add packet delays is to prevent packet collisions in multi-camera systems. Packet delay can improve reliability because it allows more time for the host CPU to process the packet, but may sacrifice speed. At the same time, setting packet delay too low (e.g., to zero) can cause packet loss if the host computer can’t keep up with packets.

Jumbo Packets¶

Jumbo packets are network packets larger than 1500 bytes. They can range in size to 9000 or more. Jumbo frames improve speed and reliability because a smaller number of larger packets are used to transfer the image, which reduces the CPU load on the host, which in turn reduces the risk of network congestion that lead to packet loss.

For information on how to configure jumbo packets, see the section on Jumbo Frames for Windows and on Jumbo Frames for Linux.

TCP¶

Transmission Control Protocol (TCP) is a fundamental internet protocol in which a connection is established between the sender and receiver using a three-way handshake before data transmission starts. This connection results in improved reliability. In addition to using the standard GigE Vision over UDP, Atlas10 cameras can also use TCP, which enables deterministic image data transfer.

See or Tech Brief on TCP in Atlas10 cameras.

RDMA¶

LUCID’s Atlas10 cameras support Remote Direct Memory Access (RDMA), which works by writing image data directly to the host’s main memory, bypassing the host’s CPU entirely.

RDMA greatly improves speed and reduces CPU load. Essentially, it prevents the vicious cycle in high-speed UDP networks where CPU resources struggle to manage packet resend, which results in more dropped packets.

For more information on how to configure jumbo packets, see the sections Configuring RDMA for Windows and Configuring RDMA for Linux.

Improving Frame Rate (Speed)¶

There are several ways you can improve the speed of LUCID cameras, and they are covered in our Knowledge Base article on improving camera frame rates.

Heat Management¶

If you use your camera at higher frame rates, heat generation may increase. See our knowledge base article on heat management for your LUCID camera for more information.

Reducing Stream Start Latency¶

Once you initiate streaming, there is latency in the time from acquisition start to when the first image is outputted. You can reduce this latency by configuring the AcquisitionStartMode node, which can be configured to Normal mode, Low Latency mode, or PTP Sync.

Normal mode is the default mode. Unless your application uses PTP Sync, we recommend that you use the Low Latency mode especially if your application would benefit from having reduced stream start latency.

Low Latency mode is designed to make your first image arrive faster after acquisition start by making the StartStream() function return more quickly. In Low Latency mode, the camera drives the image sensor in trigger mode internally even when it is streaming in free-running mode. Low Latency mode does not affect the overall transmission latency or acquisition latency.
